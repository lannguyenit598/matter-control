# Bộ phiếu ghi — usability trial (MC-ZCODE-USABILITY-PREP-20261101, mục 2)

- In được, dùng trực tiếp trong phiên. Mỗi participant một bộ: 1 phiếu đồng ý + 1 phiếu quan sát mỗi nhiệm vụ + 1 phiếu SUS + 1 phiếu tổng kết.
- **Không PII trong evidence:** phiếu đồng ý ký xong, PO giữ bản giấy/lưu riêng ngoài repo; mọi tài liệu phân tích chỉ dùng **P# + vai trò**. Không ghi tên, email, SĐT vào bất kỳ phiếu nào dưới đây.

## 1. Phiếu đồng ý tham gia (tiếng Việt)

> **PHIẾU ĐỒNG Ý THAM GIA THỬ NGHIỆM SẢN PHẨM**
>
> Sản phẩm: MatterControl — công cụ quản lý công việc pháp lý (giai đoạn thử nghiệm; toàn bộ dữ liệu trong buổi thử là **dữ liệu giả**).
> Người tổ chức: [tên PO / đại diện] — liên hệ: [địa chỉ liên hệ của PO].
>
> 1. Buổi thử kéo dài khoảng **30–45 phút** (phiên nhiệm vụ + câu hỏi + bảng câu hỏi ngắn). Tôi tham gia **tự nguyện** và có thể **dừng bất cứ lúc nào** mà không cần lý do.
> 2. Trong buổi thử, **màn hình của tôi được ghi lại** để phân tích. ☐ Tôi đồng ý ghi hình màn hình ☐ Tôi không đồng ý (chỉ ghi chép tay).
> 3. Không thu thập thông tin cá nhân (họ tên, email, SĐT) vào kết quả nghiên cứu; tôi chỉ được ghi nhận bằng **mã tham gia + vai trò công việc**. Trích dẫn ý kiến được ẩn danh theo vai trò.
> 4. Kết quả chỉ dùng **nội bộ dự án** để cải thiện sản phẩm, không công bố ra ngoài.
> 5. Bản ghi màn hình được giữ tối đa **30 ngày** kể từ ngày thử rồi xoá; ghi chép phân tích được xoá sau khi báo cáo kết quả được phê duyệt.
> 6. Tôi xác nhận tôi không cần chuẩn bị gì trước buổi thử và tôi chưa nhận bất kỳ tài liệu hướng dẫn trước nào.
>
> Mã tham gia: P___  Vai trò (đánh dấu): ☐ In-house legal (quỹ/công ty) ☐ Law firm (associate/paralegal) ☐ Manager/viewer ☐ Reviewer độc lập
> Ngày: ____/____/2026  —  Ký tên: __________________  *(bản ký do PO giữ, không lưu cùng evidence)*

## 4. Bảng câu hỏi SUS (tiếng Việt — 10 câu)

> Chọn mức đồng ý: 1 = hoàn toàn không đồng ý → 5 = hoàn toàn đồng ý. Trả lời theo cảm nhận chung.

| # | Câu | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|---|
| 1 | Tôi nghĩ rằng tôi sẽ thường xuyên muốn dùng hệ thống này | | | | | |
| 2 | Tôi thấy hệ thống này phức tạp một cách không cần thiết | | | | | |
| 3 | Tôi nghĩ hệ thống dễ sử dụng | | | | | |
| 4 | Tôi nghĩ rằng tôi cần sự hỗ trợ của một người am hiểu kỹ thuật mới dùng được hệ thống | | | | | |
| 5 | Tôi thấy các chức năng trong hệ thống được tích hợp hợp lý với nhau | | | | | |
| 6 | Tôi thấy hệ thống có quá nhiều thứ không nhất quán với nhau | | | | | |
| 7 | Tôi nghĩ đa số người dùng sẽ học cách dùng hệ thống này rất nhanh | | | | | |
| 8 | Tôi thấy hệ thống rất cồng kềnh khi sử dụng | | | | | |
| 9 | Tôi cảm thấy rất tự tin khi sử dụng hệ thống | | | | | |
| 10 | Tôi cần phải học thêm nhiều thứ trước khi dùng được hệ thống | | | | | |

**Cách chấm (note-taker tính sau phiên):** câu lẻ (1,3,5,7,9): điểm = mức chọn − 1; câu chẵn (2,4,6,8,10): điểm = 5 − mức chọn. Tổng điểm × 2,5 = điểm SUS (0–100). Ghi: ______ /100.

## 5. Chấm câu hỏi định nghĩa — phiên F

| Câu | Trả lời đúng | Đánh giá |
|---|---|---|
| Q1 hoàn tất = đã xác minh? | **Chưa** — hoàn tất là trục riêng; xác minh là trục khác, cần người xác minh độc lập chấp nhận | ☐ Đúng ☐ Gần đúng ☐ **SAI (hiểu sai — đếm vào ngưỡng cứng)** |
| Q2 biên nhận = chấp thuận? | **Chưa** — biên nhận chỉ xác nhận cơ quan đã tiếp nhận hồ sơ | ☐ Đúng ☐ Gần đúng ☐ **SAI (hiểu sai — đếm vào ngưỡng cứng)** |
| Q3 Hành động vs Yêu cầu | Hành động = việc cần làm xong; Yêu cầu = điều kiện phải có bằng chứng được xác minh | ☐ Đúng ☐ Gần đúng ☐ Sai |
| Q4 hồ sơ đã tới chấp thuận nhưng outcome chưa xác minh | **Chưa đóng** — còn chờ xác minh độc lập kết quả | ☐ Đúng ☐ Gần đúng ☐ Sai |
| Q5 yêu cầu từng bị từ chối | Phải nộp lại bằng chứng mới/bản mới; yêu cầu vẫn sống | ☐ Đúng ☐ Gần đúng ☐ Sai |

Quy tắc "Gần đúng": đúng bản chất nhưng dùng từ khác/misso nhẹ (ví dụ "phải làm lại thủ tục" cho Q5). Chỉ Q1/Q2 trả lời "Sai" mới đếm vào **hiểu sai ngưỡng cứng**.
