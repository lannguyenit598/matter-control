## Common gates, environment, evidence and cleanup

- **G-PO:** dated explicit INT-D01 choice, including temporary endpoint and transport-only evidence exclusions.
- **G-FREEZE:** selected contract frozen, case-ID literals/allowlist, reserved synthetic addresses, harness root/allowed paths and exact source versions pinned. No re-review of closed Step02.3 wording merely for reassurance.
- **G-OWNER:** exact per-repository task contract issued after approval, separate owner worktree and actual head/cleanliness checked, explicit acknowledgement; no mutation of retained native-evidence worktrees.
- **G-ENV:** before any data request, Codex supplies a verified fresh empty DB/user, capped/labelled owned resources, unused loopback ports and secret-safe DSN handoff. ENV creation/verification cases establish this gate; they do not circularly require an already provisioned DB. No resource is created in this step.
- **E-LOCAL-INTA:** future synthetic isolated local Next development-server harness + unchanged native Go52b60a4 + real newly owned PostgreSQL. No mock/in-memory stand-in; no browser/product session/IdP/real legal data/paid provider. Installed versions/heads and valid owner tools verified at dispatch. A future Next runtime guard check is not production deployment.
- **E1:** per-action exact argv or UI/procedure, UTC start/end/exit, actual tool/version/head, ownership/labels/limits/ports, empty DB identity, config hashes with secrets omitted, container/storage/process identity and retained lifecycle logs.
- **E2:** per-request unique requestId, actual Next execution, mode, exact sent method/fixed route, UTC/latency, response/error envelope and expected-versus-observed assertion. Client-success status/headers are not observable: numeric success statuses in the canonical contract remain expected upstream behavior, not client-proven facts. Wire controls have separate request IDs; no duplicate writes to obtain headers. Truncated body cannot satisfy complete-body assertions; unknown POST stays unknown without retry.
- **E3:** immediate read-only pre-restart checkpoints and post-restart reads, no intervening mutation; same DB/container/storage identity. Optional DB-stopped-before-PATCH variant requires the ordered causal chain in the canonical matrix; never infer unchanged from503 alone.
- **E4:** correlated owned application-log samples, scan command/pattern provenance and counts, no body values in application logs; credential/DSN/token values absent from all evidence. Controlled synthetic response artifacts may contain bounded synthetic values. A limited scan is not a general privacy guarantee.
- **E5:** exact base/head/diff and dependency/lockfile hashes, approved allowed paths, product artifact/module/import exclusion and guard observations; source facts are not installed-runtime proof.
- **E6:** immutable approved contract/PO record, actual owner and independent QA returns, finding/variance disposition. Conformance is document/evidence review unless actual runtime is explicitly executed and recorded; no self-awarded product/architecture/cost acceptance.
- **C1:** stop only owned processes/containers, record exit and no owned listeners, retain evidence and controlled synthetic storage; no deletion/prune/volume reuse or cleanup of others. Do not issue generic record deletion or mutate historical fixtures. Record any failure; do not claim graceful stop from later absence alone.
- **C2:** after guard-negative cases, restore only the run-specific process environment to its approved safe state. Never enable product anonymous/shared-token modes or edit global agent permissions.
- **C3:** manage only the exact owned PG container; do not remove/recreate it during durability checks. Record stop/start and storage identity. Recover it after the fault phase as specified; reconcile known-ID writes read-only, retain unresolved POST outcome; no retry/list/SQL expansion.
- **C4:** stop the exact owned Go process for T12. Restart only if an approved later procedure requires it, with new lifecycle evidence; never repeat a failed write. Final teardown covers it even when already stopped.

Reviewers: OpenCode independently verifies future execution; Claude remains Solution Architecture Authority for material deviations and later conformance where the original row requires it. The current-round OpenCode clarification closure remains intact.
