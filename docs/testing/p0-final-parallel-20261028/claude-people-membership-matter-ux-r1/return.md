## 1. Implemented behavior

- **Searchable person picker** `components/molecules/search-picker.tsx` (domain-free). One find-and-choose control: a query box (no `name`, so typed text is never submitted) over a native radio list (`name=userId`). Keyboard, grouping and form reset come from the browser; ArrowDown moves from the box into the list; Enter in the box is search, never implicit form submit. Chosen person stays pinned/checked while the query changes; Clear returns focus to the box; a `reset` event clears choice and query. States: searching, N results (+ "first matches only" when the page is full), no match (feature wording), unavailable/error with a real Retry, permission lost (no retry, pinned choice dropped), equal names ("cannot be told apart here"; no raw ids shown). Stale responses are ignored (effect cleanup + 250 ms debounce). Searches only while `active`.
- **Workspace search reaches the bounded server search** through `searchWorkspacePeopleAction` (`features/workspaces/actions.ts`): session first, Zod (`idSchema`, query trimmed ≤100), `workspaceRepository.candidates` -> `GET /workspaces/{id}/member-candidates?q=`, failures mapped 401/403 -> denied, 404/503 -> unavailable, other -> error. Returns only `{value,label}`; no token/body leakage. No client fetch, no new route handler.
- **Matter flow** filters the complete eligible list the API returns (active workspace members minus current Matter members; the endpoint returns the whole list, `page.total == n`, no cursor) by name locally.
- **Add member / Add to matter**: header action opens a dialog (`FormDialog`) -> find person -> role (with scope explanation) -> explicit submit. Copy states it is not an email invitation and distinguishes workspace from matter access (EN/VI). Success closes the dialog, `IntentForm` refreshes the route, and a status line confirms. Search text over the API's 100-**byte** bound (Go `len`) is refused locally as `invalid` with its own non-retryable message (Zod checks bytes via `TextEncoder`, not UTF-16 units); the query box `searchLabel` is localized EN/VI.
- **Close/reopen safety**: `Dialog` gained `keepMounted`; `FormDialog` uses it so an unresolved command (pending, UNKNOWN, receipted attempt) is still there on reopen. Regression proven red/green: removing `keepMounted` fails 4 tests, restoring passes.
- **IntentForm** (one line): on `unauthenticated|forbidden|not-found` it now also `reset()`s the form so a chosen person/typed values go with the dropped draft. **This applies to every form using `IntentForm` (work, proof, filings, requirements, workspace/matter creation), not only membership.** The picker re-runs its search after any reset, so it can never stay on "Searching…" (found in advisor review; red/green proven).
- **Lists** (`ListSection` + shared `LIST_CLASS`/`ROW_CLASS`): Workspaces, Matters, Workspace members, Matter members share heading, count, one primary action aligned with the heading, row density, localized role badge (Owner/Member/Editor/Viewer, Vietnamese mapping of existing enums only), empty state. Rows are one real link or a name plus the existing Remove control; no nested interactive targets. Counts use real totals only; no list search/filter/pagination was added (the endpoints back none of it).
- **Create matter / Create workspace**: one visible action opens a focused dialog; create-matter names the current workspace, explains people/documents/work come later and that you become owner with nobody added automatically (verified in `workspace_service.go` CreateMatter). Title-only command, workspace-scoped draft, stable key and exact-request retry unchanged. Success closes and navigates to `/matters/{id}?created=1`, where a banner links to `#create-work` (exists in `WorkCreationPanel`, shown only to OWNER/EDITOR) and `#matter-members`. It appears only when `?created=1` **and** the loaded data still shows you as OWNER with exactly one member, so a refresh, Back or a shared link after people were added never repeats a stale claim.
- **Workspace page** no longer reads `?people=` or fetches candidates (one fewer API call per render); it calls `connection()` before the session read (R-NX-5).
