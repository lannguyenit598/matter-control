## 3. The two mandated limitations

### L1 — Stop-at-N does not observe surplus after the stop

**Status: NOT RESOLVED.**

The packet says the reader stops after collecting `N` matches and claims `count>N` or surplus becomes `INCOMPLETE_HISTORY/ANOMALY` and “never false zero/completeness” (final P3.4/P3.5; `02-final-delta.json` `c3.patches.edge_semantics`). With the packet’s own `limit=1` trace, the reader stops at the Nth match. A later duplicate/surplus link event is unread and therefore invisible. The unconditional corruption-detection claim is unsupported.

The packet’s own `06-intake-review-focus.json` already records the counterexample `late_surplus_not_observable_after_stop` with `complete: true`, and says the claimed corruption detection “must be conditional or have an explicit broader anomaly predicate/window.” The final does not add that qualification.

**Smallest correction needed:** qualify command-local completeness to the **observed window**, or pin a bounded post-stop anomaly window (for example, process the whole page containing the Nth match, optionally one lookahead page). Do not require an unbounded scan. Separate “healthy-producer command completeness” from “corruption detection.”

### L2 — AND-filter does not self-flag wrong identity

**Status: NOT RESOLVED.**

The match predicate is strictly `type=filing.observation.evidence_linked ∧ causeSeq==mainSeq ∧ payload.observationId==O7` (final P3.1). A link event with `causeSeq=41` but `payload.observationId=O8` simply fails the predicate and is skipped. It is not reported as a mismatch. Yet final P3.4 claims “identity mismatch (match có observationId ≠ O7)” surfaces `ANOMALY`. That is internally contradictory: a row with `observationId != O7` is not a match under the AND predicate.

The packet’s own `06-intake-review-focus.json` records `wrong_identity_rejected_by_match_but_not_reported` with `complete: true`. The final does not define a separate anomaly predicate.

**Smallest correction needed:** keep the AND predicate for matching, and define a **separate** anomaly predicate over the scanned window, e.g. any event with `causeSeq==mainSeq`, `type=filing.observation.evidence_linked`, and `payload.observationId != O7` → `INCOMPLETE_HISTORY/ANOMALY`. Alternatively, explicitly drop the identity-mismatch detection claim and state it is not detected. Do not weaken the match predicate from AND to OR.

### F10-OC-01 — [High] C2 effective-view derivation omits superseded replacement observations

- **Location**: `01-final-owner-confirmation.txt` §1 C2 **P2.2**; `02-final-delta.json` `c2.patches.effective_view`; `03-C1-C2-R2-delta.json` `clause2_correction.terminal_rule`.
- **Exact clause**: P2.2 defines effective linkage as “các evidence link của observation **không bị target bởi correction terminal** trong lịch sử đã commit đến snapshot đó.” P2.1 separately says “replacement của correction superseded mất hiệu lực trong cùng commit; tối đa một replacement hiệu lực/observation gốc.”
- **Trigger A**: O4 has links; C1 `REPLACE O4→O5`; C2 `RETRACT O4` (terminal). P2.2 excludes O4 because it is targeted, but O5 is **not** targeted by a correction. Read literally, O5’s links remain effective, contradicting the R2 example that O4 and O5 are both ineffective.
- **Trigger B**: C1 `REPLACE O4→O5`; C2 `REPLACE O4→O6`. O5 is not targeted; P2.2 would keep O5 and O6 effective, violating “at most one effective replacement.”
- **Impact**: Effective/unbound totals and B3/provenance can include stale replacement links. A5/A6 cannot pass as written. History immutability itself is not broken; the derivation is.
- **Smallest correction**: replace P2.2 with one explicit per-original derivation: for each original observation, find the terminal correction (maximum `seq` among corrections whose `correctsObservationId` equals that original); no correction → original links effective; `RETRACT` → none; `REPLACE` → only links of the replacement observation created by that terminal correction; all replacement observations created by superseded corrections are ineffective; corrections targeting replacement observations → 422. Put this in P2.1/P2.2 and the JSON, not only in R2.
- **Expected cases**:
  - A5a `REPLACE O4→O5` then `RETRACT O4`: zero effective links from the O4/O5 lineage.
  - A5b `REPLACE O4→O5` then `REPLACE O4→O6`: only O6 effective; O5 ineffective.
  - A5c two originals with interleaved corrections: terminal is per original, not the latest correction in the filing.
  - A5d correction targeting O5: 422, no correction-of-correction.
  - A6 asOf before/between/after corrections: derived view changes without history rewrite.
- **Owner**: Claude (contract derivation) + Codex (document intake). This is an integration fix, not a new policy.

### F10-OC-02 — [High] C3 “never false completeness” overclaims surplus detection after stop

- **Location**: `01-final-owner-confirmation.txt` §1 C3 **P3.3–P3.5**; `02-final-delta.json` `c3.patches.emission_rules`, `c3.patches.edge_semantics`, `c3.patches.completion`; `04-C3-R3-delta.json` `path_A_recommended.stop_condition`.
- **Exact clause**: P3.4 says “`exhausted<N` … hoặc `count>N` hoặc `identity mismatch` → surface `INCOMPLETE_HISTORY/ANOMALY`; never false zero/completeness.” P3.5 says finding N unique exact matches is command-local complete even if later history is unscanned.
- **Trigger**: main event N=2; matches at seq 42 and 44; the reader stops. A third matching link event at seq 46 (duplicate/corrupt producer history) is never read; the reader reports complete. The packet’s `limit=1` trace makes this concrete.
- **Impact**: The unconditional “never false completeness” and the A8 surplus case are not achievable with stop-at-N. A corrupt producer can pass as complete. Command-local completeness under the healthy emission invariant remains sound; the defect is the overbroad corruption guarantee.
- **Smallest correction**: state that completeness is guaranteed **within the observed window** and define the window (e.g. through the page containing the Nth match, with an optional one-page lookahead). Define `surplus` as an observed matching event after N within that window. State that later surplus is outside the guarantee and does not invalidate the healthy-producer command-local completion. Do not require an unbounded scan. Update A8 to separate healthy completion from corruption detection.
- **Expected cases**:
  - A8a N=0: complete 0/0, no link scan, no false anomaly.
  - A8b exhausted<N: `INCOMPLETE_HISTORY/ANOMALY`.
  - A8c observed match count > N within the pinned window: anomaly.
  - A8d surplus only after the stop page: **not claimed detected**; no “corruption-free” assertion.
  - A8e page boundary at the Nth match: window definition and result are deterministic.
- **Owner**: Claude (reader contract) + Codex (document intake).

### F10-OC-03 — [High] C3 AND predicate cannot produce the claimed identity-mismatch anomaly

- **Location**: `01-final-owner-confirmation.txt` §1 C3 **P3.1 vs P3.4**; `02-final-delta.json` `c3.patches.predicate` vs `c3.patches.edge_semantics`; `04-C3-R3-delta.json` `path_A_recommended.discovery`.
- **Exact clause**: P3.1 makes `payload.observationId==O7` part of the normative AND. P3.4 nevertheless says identity mismatch “match có observationId ≠ O7” → `ANOMALY`.
- **Trigger**: link event with `causeSeq=41`, `type=filing.observation.evidence_linked`, `payload.observationId=O8`. The AND predicate rejects it as a non-match; no anomaly is emitted; the reader completes using O7’s N matches.
- **Impact**: Cross-observation or corrupt link rows are silently ignored. The identity-mismatch anomaly case in A8 cannot pass as specified. This is a direct contradiction, not merely a residual limitation.
- **Smallest correction**: separate the **match** predicate (AND, unchanged) from an **anomaly** predicate over the scanned window. Anomaly candidate: any scanned event with `causeSeq==mainSeq` and `type=filing.observation.evidence_linked` whose `payload.observationId != O7` (and/or whose target is not in the expected link set) → `INCOMPLETE_HISTORY/ANOMALY`. Or explicitly remove the identity-mismatch guarantee and state it is not detected. Pin the scan window in either case.
- **Expected cases**:
  - A8f O8 link under causeSeq 41: anomaly (if anomaly predicate adopted) or explicit “not detected.”
  - A8g unrelated event with causeSeq 41 but different type: ignored, no anomaly.
  - A8h unrelated link with causeSeq != 41: ignored, no anomaly.
  - A7 normal interleaving with a derived event between links: no false anomaly.
  - Page boundary around the mismatched row: deterministic result.
- **Owner**: Claude (reader contract) + Codex (document intake).

### F10-OC-04 — [High] C1 P1.3 is global, incomplete on 422, and lacks a per-command CAS/precondition matrix

- **Location**: `01-final-owner-confirmation.txt` §1 C1 **P1.3** (and P1.2); `02-final-delta.json` `c1.patches.check_ordering`; `03-C1-C2-R2-delta.json` `clause1_lifecycle.observation_target_vs_cas` / `supplement_request`.
- **Exact clause**: P1.3 defines “admission → scope lock + authorization → idempotency replay → preconditions (428/412, gồm If-Match và expectedCycleNo) → state/stage guards (409) → effects” and says it applies “đều cho mọi command.” P1.2 says a body `cycleNo` that does not exist under the filing is `422 validation`.
- **Trigger A — scope**: any command outside filing/observation/correction. P1.3 would impose a global command-order change, contrary to the F10 boundary “không áp global command order ngoài phạm vi” and the review focus IR-F10-03.
- **Trigger B — missing 422 placement**: a request with an invalid target `cycleNo`, a stale `expectedCycleNo`, and a changed stage. P1.3 lists 428/412 preconditions and 409 guards, but does not place the 422 target-binding validation. The outcome is not deterministic; if 422 is placed in “admission” before authz, it may leak target existence.
- **Trigger C — per-command CAS ambiguity**: supplement is described with `expectedCycleNo`; corrections are described in R2 with `If-Match` filing revision + `expectedCycleNo`; P1.3 says “gồm If-Match và expectedCycleNo” without saying which command uses which. Missing `If-Match`/`expectedCycleNo` also has no pinned 422/428 behavior.
- **Impact**: Unscoped global contract change; nondeterministic 422/412/409 precedence; possible authorization/existence leak; A2/A3 are insufficient to test the order.
- **Smallest correction**: scope P1.3 explicitly to the filing family (filing-create, supplement, observation, corrections); state other commands keep their existing contracts. Add a small per-command matrix for: body target binding (422), `If-Match` (428 missing / 412 stale), `expectedCycleNo` (422 missing / 412 stale), stage guard (409), and idempotency replay. Place the 422 target-binding check after authorization and replay, with an explicit 422-vs-412-vs-409 precedence. If a truly global order is desired, route it as a separate Claude/PO change, not this F10 addendum.
- **Expected cases**:
  - A2 concurrent supplement, stale CAS + changed stage → 412.
  - A2b invalid target cycleNo + stale expectedCycleNo → the pinned precedence (422 or 412; must be explicit).
  - A2c invalid target cycleNo + changed stage → the pinned precedence (422 or 409).
  - A2d missing expectedCycleNo → 422/428 as pinned.
  - A3 stage-only change + valid CAS → 409, no mutation.
  - A4 injected failure → full rollback, no event.
  - A2e correction: missing If-Match → 428; stale → 412; target not original → 422; stage guard → 409.
  - A non-filing command regression check confirms its existing order is unchanged.
- **Owner**: Claude (command contract) + Codex (document intake).

### F10-OC-05 — [Medium] C2 “latest-seq terminal” is not explicitly scoped per original

- **Location**: `01-final-owner-confirmation.txt` §1 C2 **P2.1/P2.2**; `02-final-delta.json` `c2.patches.actions`; `03-C1-C2-R2-delta.json` `clause2_correction.terminal_rule`.
- **Exact clause**: P2.1 says “latest-seq terminal” and P2.2 says “correction terminal,” but neither states that “latest” means **latest correction targeting the same original observation**, not the latest correction in the filing.
- **Trigger**: two originals O4 and O9 have interleaved corrections. A literal global “latest correction by seq” would select only one terminal for the filing and leave the other original’s corrections misclassified. A correction targeting a replacement observation O5 could also be read as allowed unless explicitly rejected.
- **Impact**: Wrong terminal selection; nondeterministic effective view; correction-of-correction ambiguity.
- **Smallest correction**: state “terminal correction = maximum `seq` among corrections whose `correctsObservationId` equals the same original observation; latest is per original, not per filing; corrections targeting replacement observations are rejected 422.” Add to P2.1/P2.2 and A5.
- **Expected cases**:
  - A5e interleaved corrections on O4/O9: each original has its own terminal.
  - A5f correction targeting O5: 422.
  - A5g repeated REPLACE on the same original: latest terminal only; earlier replacement ineffective.
- **Owner**: Claude/Codex.

### F10-OC-06 — [Low] Proposed numeric bounds lack units and envelope definition

- **Location**: `01-final-owner-confirmation.txt` §1 Projection (numeric bounds); `02-final-delta.json` `projection.numeric_bounds`.
- **Exact clause**: proposed `reason<=2000`, `type<=64`, `correlationId<=128`; `correlationId` says “chars,” but `reason`/`type` do not state Unicode code points vs UTF-8 bytes, inclusive/exclusive limit, or envelope size.
- **Trigger**: a 2000-character reason with multi-byte UTF-8; a 2000-byte reason; an envelope larger than an unstated server limit. Client and server can disagree at the boundary.
- **Impact**: Cross-language validation ambiguity; proposed bounds are not fully testable; the packet correctly avoids a constant-byte claim, but the bounds are not yet a precise proposed contract.
- **Smallest correction**: state the unit and inclusivity for each proposed bound; either propose an envelope bound or explicitly mark it `NEEDS_AUTHORIZED_SOURCE`; keep the “proposed, not source-proven” label.
- **Expected cases**: P5a boundary at 2000 code points vs 2000 UTF-8 bytes; P5b envelope oversize/deferred; P5c correlationId 128 chars; no constant-byte claim.
- **Owner**: Codex (document) / PO at the contract gate.
