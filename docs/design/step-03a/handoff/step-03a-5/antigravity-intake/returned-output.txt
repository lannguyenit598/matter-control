## 1. Independent Verification of Codex Observations

We performed a direct, line-by-line inspection of the reference starter codebase at `/tmp/mattercontrol-step02-frontend`:


### 1.1 Presentational `DataTable` ([`data-table.tsx`](file:///tmp/mattercontrol-step02-frontend/src/components/organisms/data-table.tsx#L1-L69))
- **Observation Verified**: [`DataTable`](file:///tmp/mattercontrol-step02-frontend/src/components/organisms/data-table.tsx#L28-L68) is strictly a presentational HTML wrapper (`<div className="overflow-x-auto rounded-lg border bg-card"><table>...</table></div>`).
- **Gaps for MatterControl**:
  - Contains **zero row selection** logic (no checkboxes, no multi-select, no `is-selected` state).
  - Contains **zero keyboard navigation** (no row arrow `Up`/`Down`, no `Enter`/`Space` activation, no `role="grid"` or `aria-rowindex`/`aria-colindex` attributes).
  - Contains **zero inline editing** capability (no input cells, no local error boundary, no `Enter` commit or `Escape` cancel).
  - Contains **zero density adaptation** (fixed row padding `px-4 py-3`, no Comfortable 44px vs Compact 36px row minimum with multiline expansion).
  - Does **not** provide spreadsheet paste, column resizing, bulk state management, or five-axis display.
  - **Conclusion**: `DataTable` cannot serve as the Operational Grid without fundamental replacement or deep adaptation into a full Grid organism.

### 1.2 Native `Dialog` ([`dialog.tsx`](file:///tmp/mattercontrol-step02-frontend/src/components/molecules/dialog.tsx#L1-L110))
- **Observation Verified**: [`Dialog`](file:///tmp/mattercontrol-step02-frontend/src/components/molecules/dialog.tsx#L25-L109) utilizes native `<dialog>` and `showModal()`, granting browser-level focus trapping, top-layer rendering, and backdrop click handling.
- **Risks & Gaps Identified**:
  - Line 82: `{open && <div ...>{children}</div>}` unmounts children as soon as `open === false`. Any uncommitted form state, draft, or validation error inside the dialog is immediately destroyed upon close unless explicitly lifted to an external state container.
  - Line 47: Focus restoration relies entirely on the browser's default behavior (returning focus to the opener element). If the opener was a row item or action trigger that disappeared due to concurrent filtering, sorting, or pagination, focus drops to `document.body`. A robust labeled fallback focus target is missing.
  - No side-sheet / drawer primitive exists for the contextual impact rail, object detail drawers, or Evidence review panels.

### 1.3 `MobileNav` ([`mobile-nav.tsx`](file:///tmp/mattercontrol-step02-frontend/src/components/organisms/mobile-nav.tsx#L1-L40))
- **Observation Verified**: [`MobileNav`](file:///tmp/mattercontrol-step02-frontend/src/components/organisms/mobile-nav.tsx#L15-L39) is solely a menu trigger button (`<Menu />`) opening a slide-out navigation menu (`<NavMenu items={items} />`) styled via `h-dvh max-h-dvh w-72`.
- **Gaps for MatterControl**:
  - Does not implement mobile triage, mobile record cards, full-screen record detail views, or permitted simple action workflows.
  - The menu toggle button uses `Button size="icon"` (`size-9` = 36px), falling below the D-UX04 / `selected-tokens.css` 44px minimum touch target specification (`--mc-touch-min: 44px`).

### 1.4 Generic `TaskRepository` ([`types.ts`](file:///tmp/mattercontrol-step02-frontend/src/features/tasks/types.ts#L26-L32) & [`actions.ts`](file:///tmp/mattercontrol-step02-frontend/src/features/tasks/actions.ts#L1-L78))
- **Observation Verified**: `TaskRepository` exposes a standard CRUD interface (`list`, `stats`, `create`, `update`, `remove`) targeting a flat `Task` model (`title`, `description`, `status`, `priority`, `dueDate`).
- **Gaps for MatterControl**:
  - Lacks Matter, Workstream, and Requirement vs. Action domain entities.
  - Directly sets status via dropdown, violating the immutable domain rule that state is independently evaluated across 5 distinct axes (Execution, Verification, Dependency, Timing, Attention).
  - Lacks Evidence Requirement linkage, proof verification with designated independent verifiers, document version lineage, and regulatory filing lifecycle stages.
  - Contains no bulk editing transactions following RULE-013 (per-record atomic mutation, allowlisted fields, revision validation, failed row retention, and persistent retry selection).
  - `src/lib/auth-provider.ts` defaults to fail-closed (`resolveSession()` returns `null` with a console warning); demo mode bypasses auth entirely with `{ userId: 'demo', permissions: ['*'] }`. Production authorization enforcement remains unimplemented.

## 6. Keyboard & Accessibility Requirements Audit

### 6.1 Nested Editor Keys & Grid Focus Traps
- **Requirement**: While editing within an inline cell input or textarea, standard typing and editing keys (`ArrowLeft`, `ArrowRight`, `Home`, `End`, `Space`, `Backspace`, `Delete`) must remain trapped inside the native text control and must **never** bubble up to trigger grid row navigation, record selection, or drawer dismissal.
- **Starter Defect**: [`DataTable`](file:///tmp/mattercontrol-step02-frontend/src/components/organisms/data-table.tsx#L56-L64) lacks keyboard event handlers entirely. An `OperationalGrid` implementation must explicitly check `event.target` in its `onKeyDown` listener: if the active target is an `INPUT`, `TEXTAREA`, or `SELECT`, grid navigation hotkeys (`ArrowUp`, `ArrowDown`, `Space`) must be ignored.
- **Recovery**: Pressing `Enter` inside an inline editor submits the validated patch; pressing `Escape` cancels the edit, reverts the cell to its server-confirmed value, and returns focus to the containing cell without shifting row selection or viewport scroll.

### 6.2 Selection, Inline, and Bulk Error Recovery
- **Inline Cell Errors**: If an inline edit fails client-side validation (e.g., empty title, invalid date) or backend mutation (e.g., `409 Conflict`), the cell must retain the user's uncommitted draft, visually highlight the error with `--mc-danger` (`#a12622`) and `aria-invalid="true"`, and display an adjacent error tooltip/announcement. The row must remain selected and the table must not clear filter or sort context.
- **Bulk Edit Failure Recovery**: Under RULE-013, bulk mutations commit atomically per record. If 3 of 10 rows fail due to permissions (`403`) or revision conflicts (`409`), the 7 successful rows deselect and update, while the 3 failed rows **remain selected in the Grid**. The bulk modal/banner must persist a summary of failed IDs with specific reasons and a dedicated "Retry Failed Only" action.

### 6.3 Dialog Draft Preservation & Focus Restoration Fallback
- **Starter Defect in [`Dialog`](file:///tmp/mattercontrol-step02-frontend/src/components/molecules/dialog.tsx#L82)**: Because `{open && children}` unmounts on close, temporary dismissals (such as accidental backdrop clicks or checking an underlying value) destroy unsubmitted forms.
- **Remediation**: Form state must be managed via an external Zustand store or React Hook Form context external to the mounting boundary, or the dialog must support an explicit draft confirmation check before unmounting.
- **Focus Restoration Fallback**: In standard browser behavior, `dialog.close()` returns focus to the opener element. However, if the opener row was removed (e.g., completed or filtered out while the dialog was active), focus drops to `document.body`. The dialog manager must verify `document.contains(triggerElement)`: if false, it must fall back to a labeled container (e.g., the table header or filter bar) via `focusFallbackId`.

### 6.4 Textual Status, Non-Color Axes & Screen Reader Feedback
- **Non-Color Semantics**: Color alone must never convey state. Every badge, cell, and list item must explicitly render the textual state label and reason (e.g., `BLOCKED: Missing ER-02 Board Approval`, not just a red icon).
- **Live Regions**: Asynchronous status updates (e.g., inline save confirmation, bulk progress, background evaluator error) must output to an accessible live region (`role="status"` with `aria-live="polite"` for non-critical updates; `role="alert"` with `aria-live="assertive"` for fatal or security errors).

### 6.5 Mobile Reachability, Zoom & Touch Targets
- **No Record Truncation**: Mobile card lists must render **all** matching records. The legacy concept truncation (first 8 rows) is explicitly forbidden. Users must be able to scroll, search, and paginate through every record.
- **Touch Target Geometry**: All interactive elements on mobile viewports ($\le 760\text{px}$) must satisfy the `--mc-touch-min: 44px` minimum hit area (`min-height: 44px`, `min-width: 44px`), including icon buttons, close triggers, and filter chips.
- **200% Zoom & Reflow**: Layouts must reflow into a single column at $200\%$ browser zoom ($1280\text{px} \to 640\text{px}$) without horizontal scrolling for primary prose or clipping of critical blocker descriptions and decision queues.

### 6.6 Reduced Motion & Computed Contrast
- **Reduced Motion**: When `prefers-reduced-motion: reduce` is active, all CSS transitions, dialog animations, and pulse effects must be disabled (`animation: none !important; transition: none !important;`), while fully preserving color contrast and text visibility.
- **Computed Contrast Verification Status**: The theoretical sRGB token pairs in `selected-tokens.css` meet WCAG AA ($4.5:1$ for body ink `#17212b` on `#ffffff` $\approx 14.8:1$; `#52606d` on `#ffffff` $\approx 5.3:1$). However, computed contrast across hover, active, focus-visible (`#174ea6` 2px ring), and disabled states (`#626973` on `#eef2f6` $\approx 4.6:1$) has **not** been measured under actual browser rendering and remains formally `NOT_TESTED`.
